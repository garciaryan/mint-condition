# Go Online Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the existing Mint Condition app on Fly.io behind a single-password login, with a SQLite foundation ready for Phase 4.

**Architecture:** Pure auth logic lives in `lib/auth.ts`, which uses only Web Crypto, and `lib/password.ts`, which uses `node:crypto` scrypt.
A pure `gate()` decides each request; `middleware.ts` is a thin wrapper around it. `lib/db.ts` opens a `node:sqlite`
singleton and runs a tiny migration runner. Next builds a standalone server, which the Docker image runs on one Fly machine
with a volume at `/data`.

**Tech Stack:** Next.js 15.5 App Router, TypeScript, Node built-ins only (`node:crypto`, `node:sqlite`, `node:test`), Fly.io.

**Spec:** `docs/superpowers/specs/2026-10-04-go-online-design.md`

## Global Constraints

- No new npm dependencies. Node built-ins only.
- Node 22.13+ locally (unflagged `node:sqlite`). The Docker image is `node:24-slim`.
- Imports use explicit `.ts` extensions, matching the existing code (`allowImportingTsExtensions`).
- Cookie: name `mc_session`, value `<expiresAtMs>.<HMAC-SHA256 b64url>`, `HttpOnly`, `Secure` in production, `SameSite=Lax`, `Path=/`, `Max-Age=2592000` (30 days).
- Password hash format: `scrypt$<N>$<r>$<p>$<salt b64>$<hash b64>`, with N=16384, r=8, p=1, 16-byte salt, 32-byte key.
- Login limiter: 5 failures per IP per 15 minutes. Failed attempts wait 500 ms.
- Public paths: `/login`, `/api/login`, `/api/health`, `/_next/*`, `/favicon.ico`.
- Error responses reuse the existing JSON shape: `{ status: "error", kind, message }`.
- Never return or log secret values. Report variable names and presence only.
- Exactly one Fly machine. Do not scale out.
- `npm test`, `npm run typecheck` and `npx next build` must pass after every task.

## Review Focus

1. **Malformed cookies** (empty, no dot, extra dots, non-numeric expiry, huge expiry with a bad signature) make `verifySession` return `false` and never throw. Test in Task 1.
2. **Open redirect through `?next=`**: `//evil.com`, `/\evil.com`, `https://evil.com`, `javascript:alert(1)` and `%2F%2Fevil.com` all become `/`. Test in Task 1.
3. **Look-alike public paths**: `/loginx`, `/api/login/x`, `/api/healthz` and `/_nextx` are not public. Test in Task 1.
4. **Bad login bodies** (not JSON, missing password, non-string password) get a 400 response, never a 500. Test in Task 3.
5. **A correct login clears that IP's failure count**, so 4 failures, then a success, then 4 more failures is not blocked. Test in Task 1 (limiter) and Task 3 (route).

`authMode` rules: with `NODE_ENV=production`, both `APP_PASSWORD_HASH` and `SESSION_SECRET` set gives `on`, otherwise

```ts
test("verifyPassword accepts the right password, rejects wrong and malformed", () => {
  const h = hashPassword("crate digger");
  assert.match(h, /^scrypt\$16384\$8\$1\$[^$]+\$[^$]+$/);
  assert.equal(verifyPassword("crate digger", h), true);
  assert.equal(verifyPassword("crate diggers", h), false);
  for (const bad of ["", "scrypt$1$2", "bcrypt$x$y$z$a$b", "scrypt$16384$8$1$!!$!!"]) assert.equal(verifyPassword("x", bad), false);
});
test("session cookies verify until expiry and reject tampering", async () => {
  const v = await signSession("s3cret", 1_000);
  assert.equal(await verifySession(v, "s3cret", 1_000 + 1), true);
  assert.equal(await verifySession(v, "s3cret", 1_000 + SESSION_MAX_AGE_S * 1000 + 1), false);
  assert.equal(await verifySession(v, "other", 2_000), false);
  const [exp, sig] = v.split(".");
  assert.equal(await verifySession(`${Number(exp) + 1}.${sig}`, "s3cret", 2_000), false);
});
test("malformed cookies return false without throwing", async () => {
  for (const bad of [undefined, "", "abc", "1.2.3", "x.y", "999999999999999.AAAA", ".", "1."])
    assert.equal(await verifySession(bad, "s3cret", 0), false);
});
test("authMode", () => {
  assert.deepEqual(authMode({}), { mode: "off" });
  assert.deepEqual(authMode({ APP_PASSWORD_HASH: "h", SESSION_SECRET: "s" }), { mode: "on", passwordHash: "h", secret: "s" });
  assert.deepEqual(authMode({ SESSION_SECRET: "s" }), { mode: "misconfigured", missing: ["APP_PASSWORD_HASH"] });
  assert.deepEqual(authMode({ NODE_ENV: "production" }), { mode: "misconfigured", missing: ["APP_PASSWORD_HASH", "SESSION_SECRET"] });
  assert.deepEqual(authMode({ NODE_ENV: "production", APP_PASSWORD_HASH: " ", SESSION_SECRET: "s" }).mode, "misconfigured");
});
test("isPublicPath matches exact public paths only", () => {
  for (const p of ["/login", "/api/login", "/api/health", "/_next/static/x.js", "/favicon.ico"]) assert.equal(isPublicPath(p), true, p);
  for (const p of ["/", "/loginx", "/api/login/x", "/api/healthz", "/_nextx", "/api/lookup"]) assert.equal(isPublicPath(p), false, p);
});
test("safeNext only allows same-origin relative paths", () => {
  assert.equal(safeNext("/collection?id=3"), "/collection?id=3");
  for (const bad of [null, "", "//evil.com", "/\\evil.com", "https://evil.com", "javascript:alert(1)", "%2F%2Fevil.com", "evil"])
    assert.equal(safeNext(bad), "/", String(bad));
});
test("limiter blocks after 5 failures, resets after the window and on success, per IP", () => {
  const l = createLoginLimiter();
  for (let i = 0; i < 5; i++) l.fail("a", 0);
  const blocked = l.check("a", 1_000);
  assert.equal(blocked.ok, false);
  assert.equal(!blocked.ok && blocked.retryAfterMs, 15 * 60_000 - 1_000);
  assert.equal(l.check("b", 1_000).ok, true);
  assert.equal(l.check("a", 15 * 60_000).ok, true);
  const m = createLoginLimiter();
  for (let i = 0; i < 4; i++) m.fail("a", 0);
  m.reset("a");
  for (let i = 0; i < 4; i++) m.fail("a", 0);
  assert.equal(m.check("a", 0).ok, true);
});
test("clientIp prefers Fly-Client-IP, then the first X-Forwarded-For entry, then 'local'", () => {
  assert.equal(clientIp(new Headers({ "fly-client-ip": "1.1.1.1", "x-forwarded-for": "2.2.2.2" })), "1.1.1.1");
  assert.equal(clientIp(new Headers({ "x-forwarded-for": "2.2.2.2, 3.3.3.3" })), "2.2.2.2");
  assert.equal(clientIp(new Headers()), "local");
});
test("configStatus reports presence only, and requires login vars unless login is off", () => {
  const s = configStatus({ DISCOGS_TOKEN: "t", DISCOGS_USER_AGENT: "u" });
  assert.deepEqual(s, { ok: true, vars: { DISCOGS_TOKEN: true, DISCOGS_USER_AGENT: true, APP_PASSWORD_HASH: false, SESSION_SECRET: false } });
  assert.equal(configStatus({ NODE_ENV: "production", DISCOGS_TOKEN: "t", DISCOGS_USER_AGENT: "u" }).ok, false);
  assert.ok(!JSON.stringify(configStatus({ DISCOGS_TOKEN: "secret-value" })).includes("secret-value"));
});
```

### Task 3: Request gate, login and logout routes, login page, client handling

**Files:**
- Create: `lib/gate.ts`, `middleware.ts`, `app/api/login/route.ts`, `app/api/logout/route.ts`, `app/login/page.tsx`, `app/login/LoginForm.tsx`, `app/LogoutButton.tsx`

- Test: `tests/gate.test.ts`, `tests/login.test.ts`

**Interfaces:**
- Consumes: everything from `lib/auth.ts` and `verifyPassword` (Task 1)
- Produces:
  - `type GateRequest = { method: string; path: string; search: string; origin: string | null; host: string | null; cookie: string | undefined }`
  - `type GateResult = { kind: "pass" } | { kind: "redirect"; location: string } | { kind: "json"; status: 401 | 403 | 503; body: { status: "error"; kind: string; message: string } } | { kind: "text"; status: 503; body: string }`
  - `gate(req: GateRequest, env: Record<string, string | undefined>, now: number): Promise<GateResult>`
  - `POST /api/login` with body `{ password: string }` returns 200 `{ ok: true }` plus `Set-Cookie`, or 400/401/429/503 `{ status: "error", kind, message }`. A 429 also carries `retryAfterMinutes`.
  - `POST /api/logout` returns 200 `{ ok: true }` plus a `Set-Cookie` that clears `mc_session` (`Max-Age=0`)

`gate` checks in this order:
1. A method other than GET or HEAD whose `origin` host does not equal `host`, or that has no `origin`, gets a JSON 403 with kind `forbidden`.
2. A public path passes.
3. If `authMode` is `misconfigured`: `/api/*` paths get a JSON 503 with kind `missing-env`, and pages get a text 503. Both use the message `Login not configured: missing APP_PASSWORD_HASH` (missing names joined with " and ").
4. If `authMode` is `off`, the request passes.
5. With a valid cookie, the request passes.
6. Otherwise `/api/*` gets a JSON 401 with kind `auth` and the message `Signed out. Log in again.`, and pages redirect to `/login?next=` followed by `encodeURIComponent(path + search)`.
